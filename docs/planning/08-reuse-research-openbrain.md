# OpenBrain reuse assessment

Status: design input, 15 October 2026. Assessed [OB1 at commit `238df6c`](https://github.com/NateBJones-Projects/OB1/tree/238df6cefd307745d1fe49d10b96797903bf25ac) by reading its documentation and source. No deployed instance or comparative benchmark was run. This note compares OB1 with the *planned* Froodbase service; the current local implementation is still a walking skeleton. The earlier [Graphiti and Hindsight assessment](06-reuse-research-graphiti-hindsight.md) already informed the knowledge model, retrieval and temporal design. The direction was settled on 16 October 2026: there is no approval state; every claim is active and earns support from independent evidence roots, verifications and evidenced use outcomes; see [PR-15 and PR-40 to PR-42](01-product-requirements.md).

| Dimension | Froodbase vision | OB1 at the inspected commit |
|---|---|---|
| Purpose | Shared engineering knowledge with evidence, scope, auditable support history and human oversight | Personal memory across AI clients, with optional agent workflows |
| Canonical records | Entities, relationships, assertions and lessons with revisions and validity time | Core text thoughts with embeddings and metadata; optional Agent Memory sidecars add types, relations, review and provenance |
| Sources | Claims extracted from living repositories, Confluence pages and other sources, with references; reports are never an input and no copies are kept | Quick capture and source-specific import recipes; a documented ingestion metadata contract |
| Retrieval | Exact, text, optional vector and graph channels with per-human permission checks | Core vector search; optional agent recall adds policy metadata and usage traces |
| Oversight | All contributions, support events and decisions remain inspectable to authorised reviewers in every state | Optional review states, provenance and recall traces; the inspected agent API uses a shared key and caller-supplied actor data |

OB1's useful contribution is the *operational contract around memory*: how a person captures a finding, how an importer explains its extraction, how an agent reports whether recall helped, and how a reviewer can inspect the result. Its optional Agent Memory, provenance and editorial recipes are substantial but are not guarantees of every base OB1 installation. See its [agent-memory schema](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/schemas/agent-memory/schema.sql), [ingestion contract](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/docs/ingestion-metadata-contract.md) and [provenance evaluator](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/recipes/provenance-chains/eval.mjs).

## Adaptations to make

1. **A complete, inspectable contribution.** Make `contribute` easy to use for one source-backed observation, decision or inference. Return the created record identifiers, kinds, support and state as a receipt the agent lists in its report. Nothing from a report or conversation is sent and no original is stored. This refines PR-50 to PR-52 and TR-60, TR-63 to TR-65. OB1's [capture tool](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/server/index.ts#L439-L478) and [companion prompts](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/docs/02-companion-prompts.md) demonstrate the low-friction entry point; the receipt is a Froodbase adaptation.
2. **Import lineage and original authorship.** Preserve source identity, revision, precise locator, importer/extractor version and extracted-content fingerprint. An optional input digest can be computed without retaining the source body. Distinguish the original speaker or author, possibly unknown, from the authenticated contributor and acting agent. These fields explain re-imports and revised extraction. A fingerprint offers a duplicate *candidate*, never a reason to collapse independent evidence roots. OB1 has a [documented importer contract](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/docs/ingestion-metadata-contract.md) and an optional [speaker-attribution recipe](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/recipes/authorship-edges/lib/speaker-attribution.mjs); older importers do not uniformly implement the newer contract.
3. **Reviewable knowledge history.** The existing contribution, claim, revision and audit records provide the foundation. Give area reviewers a filtered view of *all* ingested claims and their decisions, not only the due-for-review queue. Allow any claim in a mixed batch to be flagged with a reason, which lowers its support without changing its state or validity. This is an oversight requirement independent of the eventual UI (PR-46, TR-45, TR-75). OB1's optional [review sidecar](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/schemas/agent-memory/schema.sql) illustrates the benefit of explicit review metadata; Froodbase retains its stronger per-human permission and append-only rules.
4. **Retrieval outcome reports.** Extend planned explanation traces with an append-only report of what happened when a returned record revision was used. An evidenced success is a new observation and root that raises the record's support; an evidenced failure lowers it or disputes it; inapplicable and not-used reports inform evaluation only (PR-65, TR-59). This goes further than OB1, which records usage without letting it change certainty. OB1 records [recall items and usage outcomes](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/schemas/agent-memory/schema.sql#L180-L246).
5. **Evidence sufficiency and provenance exploration.** A real citation can still be irrelevant or insufficient. Evaluate existence, relevance and sufficiency separately as a review aid that prioritises human attention; it never changes support. Expose upstream evidence and downstream dependants through bounded, permission-checked views of the existing derivation links (PR-74, PR-100, TR-85). OB1's [evaluator](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/recipes/provenance-chains/eval.mjs) and [traversal tools](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/recipes/provenance-chains/mcp-tools.ts) are useful patterns, not proof that model grades establish truth.
6. **Worked reuse and correction.** Version the investigation-agent workflow: retrieve current and historical evidence, contribute selected findings, report an outcome and show the support change, retrieve the later result, and demonstrate a maintainer retraction of an earlier false positive. Test the round trip across supported clients and an unauthorised area. OB1's [code-review memory recipe](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/recipes/openclaw-code-review-memory/README.md) shows how corrections and ignored memories can form a measurable loop. Froodbase starts with its planned investigation audience (PR-92).

## Boundaries and sequence

Keep Froodbase's existing bitemporal model, independent evidence roots, earned support with per-area thresholds, the rule that reports are never an input, per-human permissions and the rule that retrieved prose is evidence rather than an instruction. OB1's [shared-key agent API](https://github.com/NateBJones-Projects/OB1/blob/238df6cefd307745d1fe49d10b96797903bf25ac/integrations/agent-memory-api/index.ts#L199-L202) is not a substitute for those guarantees. Do not copy automatic session capture or treat multiple imports of the same source as corroboration.

The local MVP keeps its approved slice order: the schema records contribution and audit lineage first, and lifecycle review follows in slice 4. Specify importer metadata before the deferred architecture importer is built. Make contribution-history browsing, outcome reports, evidence-sufficiency evaluation, provenance exploration and workflow examples part of the pilot or later slices as identified in the [implementation plan](04-implementation-plan.md). The Flashheart board holds the implementation tickets; this document records the durable rationale, not a backlog.
